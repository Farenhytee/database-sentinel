## What went wrong
- **Verify bug:** PostgREST returns 206 (not 200) when a table has more rows than the probe's limit, so only 1 finding got verified.
- **Object granularity:** the models reported `SENSITIVE_COLUMNS` on `table.column`; labels use the table (cases 008, 011).
- **Double-reporting:** `RLS_DISABLED` alongside `POLICIES_BUT_NO_RLS` on the same table (cases 002, 014).
- **Agent false positives on clean cases:** it kept R0's false candidates (a trigger function, a private-schema helper, a public image bucket) and flagged `STORAGE_NO_RLS`.
- **Hang:** a first retry of the run stalled 29 minutes on one OpenRouter request; the client timeout didn't fire.

## Fixes applied before run 2
1. Verify accepts any 2xx.
2. `models.clean()` normalizes objects to `schema.table` and drops `RLS_DISABLED` when `POLICIES_BUT_NO_RLS` covers the table. Used by B0 and A, and by the matcher.
3. `STORAGE_NO_RLS` no longer scored: RLS is always on for `storage.objects` in Supabase. No label used it.
4. `get_schema` adds each function's return type and `auth_execute`. The prompt says only `public` is exposed, and that rule candidates are often false positives.
5. Runner: hard 5-minute deadline per system per case, and unbuffered progress output.
